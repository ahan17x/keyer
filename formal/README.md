# Formal proofs

Tools: `pip install yowasp-yosys` (provides `yowasp-sby`), `apt install z3`,
`yosys-abc` (comes with yosys).

| File | Block | Properties | Result |
|---|---|---|---|
| `fifo.sby prove` | `keyer_fifo` | count tracks pushes minus pops; empty/full/count consistent; never both | proved (k-induction, DEPTH=4 instance) |
| `fifo.sby bmc` | `keyer_fifo` | an arbitrary pushed word is read out unchanged after exactly the entries ahead of it | BMC depth 20 |
| `pins.sby` | `keyer_pins` | open-drain pins are never driven high (with the core command, replay and serializer ports and PINMODE all free); uo[1:0] fixed; level = pad two cycles earlier; level2 = level two cycles earlier; 6. a serializer write alone changes only the push-pull pins of its pair (uio_oe <= drive, uio_out <= value when driving, unchanged on release) and not od_mask | proved (k-induction) |
| `run_core_pdr.sh` | `keyer_core` | timer (T1-T8): a reached deadline completes WAITD k / a timeout-form wait in the same slot (exact completion rule); disabled timer never changes NOW; NOW moves only by a tick (+1) or to 0 on SETT / soft reset, and a due tick is never lost; DEADLINE moves only through SETD, completed WAITD, SETT, soft reset; WAITD k adds exactly k, SETD k sets NOW + k; timeout forms set C = !base, base forms leave C; prescale/period follow the tick rule; a timed-out wait pops, pushes and writes nothing; T9 a thread that executes and does not complete writes no register, keeps its flags and LR (soft reset aside) and sends no pin command, FIFO strobe or CAPC strobe, and a thread's flags change only when it commits or is soft-reset (so a blocked timeout-form wait never writes C). Control (P3-P8): PC moves only on commit or host write; threads start only via host or START; halted implies stopped; thread parity; blocked threads hold PC; P8 START and STOP act only on the other thread (absent a same-cycle host RUN write: the other's running becomes 1 / 0, START clears its halted, STOP keeps it and clears its DELAY count, the executing thread's running and halted are unchanged). Thread select (S1, D1; DECISIONS D-028): each of the four registered one-hot select copies (`sel_rf`, `sel_tm`, `sel_pc`, `sel_io`) is one-hot and equals the decode of `tid` in every cycle; `wr_en`, `z_we`, `lr_we` and `do_sett`, whose write enables use "executes" rather than "commits", are only set by instructions that complete | proved (abc pdr, about 5 s; the script exits non-zero unless abc reports "Property proved") |
| `equiv_core.sh [REF [DIR]]` | `keyer_core` | sequential equivalence of the working-tree core (or the copy in DIR) with `src/keyer_core.v` at git REF (default master): the same flops by name, and from equal state and inputs every flop input and every output equal (Yosys `equiv_make` on state and ports only, `equiv_simple`, `equiv_induct`, `equiv_status -assert`). For refactors that must not change behaviour | 533 of 533 points against master, about 8 s; exits non-zero on any unproven point |

| `capture.sby prove` | `keyer_capture` | C1 an entry produced while the queue is full (two entries, none written that cycle) sets `cap_ovf` (and drops `cap_armed`) the next cycle unless ARM lands, `cap_ovf` rises for no other reason, an entry produced with room is queued; C2 every capture write goes to `cap_base + cap_w` with `cap_w < cap_len`, i.e. inside `[cap_base, cap_base + cap_len) mod 256`, and `cap_w <= cap_n <= cap_len` (while CAP_BUF is unchanged since ARM); C3 replay entry k >= 1 is applied exactly `max(delta, 1)` cycles after entry k - 1 (own counter) with `rep_under = 0`, for every delta including 4095 (`rep_dt` equals the true elapsed count while active, never past 4095: SEMANTICS 14.7 fourth bullet, spec question Q16); C4 after `rep_under` nothing is applied and it stays set until START, and it rises exactly under the 14.7 conditions (head late, or no head at `rep_dt` = 4095); C5 trigger entry delta 0, recorded deltas = cycles since the previous entry, pins = masked nibble; C6 data integrity through the queue and the prefetch (arbitrary index j); C7 engines use only free cycles (14.1), capture before replay; C8 `cap_done` and capture-active definitions, the prefetch is empty while the replay is inactive; C9 no underrun while the port has been free in every cycle since START, whatever the deltas; C10 ARM / DISARM / START / STOP effects, `rep_n` = `rep_len` or `cap_w`. All inputs free except a reset in cycle 0 | proved (k-induction depth 4, z3, about 1 s) |
| `capture.sby cover` | `keyer_capture` | non-vacuity: entry 2 written, an overflow, replay entry 2 applied, an underrun, a three-entry capture done, entry 4 applied one cycle after entry 3 | all reached within 10 steps |
| `ser.sby stuff` | `keyer_ser` | every input free (SERCFG of any value at any time, bytes, marks, ticks, periods, levels, SERRX), reset in cycle 0 only, engine observed only at its ports (`ser_txmon.sv` decodes the emitted bit stream from the pin writes). S1 with stuff = 1, in both modes, the bits handed to the line coder (data, CRC, stuffed) never contain seven consecutive ones; S2 NRZI, stuff = 1, a frame that starts with P low: the pair, as written by the engine, keeps its value through at most six consecutive symbol ticks between the start tick and the tail's SE0; S3 inside a frame every engine write is line(s) or se0() and a Manchester second half is the complement of its first | proved (abc pdr, about 1 s) |
| `ser.sby crc_any` | `keyer_ser` | the same free environment with every byte marked. Q1 throughout DATA and CRC, `crc_m` equals the reflection of an incremental textbook (MSB-first, non-reflected generator 0x8005 / 0x04C11DB7) reference fed with the unstuffed bits decoded from the wire; Q2 the bits sent in CRC are its complement, exactly 16 or 32 of them. Any frame length, either CRC, either mode, stuffing on or off | proved (abc pdr, about 35 s) |
| `ser.sby crc16`, `crc32` | `keyer_ser` | a symbolic 2-byte message, all marked, queued without a gap, ticks every cycle. R1 `crc_m` at the end of the data equals the whole-message reference of `ser_crc_ref.vh`; R2 the frame decoded from the pin writes, stuffed bits removed, is exactly the message, the complemented CRC bit 0 first, then the tail; R3 the frame ends by a fixed cycle; R4 known answers ("123456789": CRC-16/USB B4C8, CRC-32 CBF43926; USB token CRC-5 00010; the first two bytes "12": registers F595 and B0ACBB32, computed with zlib / MSB-first division in Python). crc16: NRZI or Manchester, stuffing on or off; crc32: either mode, no stuffing | BMC depth 88 / 126 (abc bmc3, about 6 s / 45 s) |
| `ser.sby rt_nrzi`, `rt_manch` | two `keyer_ser` | transmitter pin writes -> pads (bus pulls give J when released) -> two-flop synchroniser -> receiver, same configuration, period T (4 NRZI, 2 Manchester), tick phase, pin pair k and the other pads free, always-ready SERRX. Frame: sync (0x80 / 0xD5), one symbolic message byte, CRC-16 appended; NRZI with stuffing, Manchester stuffing free; rxskip free where the frame has a PID. T1 the receiver delivers exactly the message byte, then the two CRC bytes (the complemented reference), then one frame end with `rx_cok` = 1 and no frame, stuffing or overrun error; T2 `crc5` at that end equals the reference CRC-5 of the received bits and `rx_c5ok` agrees; T3 the end comes by a fixed cycle | BMC depth 200 / 190 (abc bmc3, about 80 s / 30 s) |
| `ser.sby *_cover` | | non-vacuity: a full NRZI and a full Manchester frame with a stuffed bit, the line held six ticks; the known-answer message reaching the end of its data and both modes' frames ending; a CRC-16 frame, CRC-32 bits going out and a stuffed bit inside the CRC in the free environment; the first byte through the round trip | all reached (smtbmc z3, about 1 min in all) |

Run: `yowasp-sby -f fifo.sby`, `yowasp-sby -f pins.sby`, `./run_core_pdr.sh`,
`yowasp-sby -f capture.sby`, `yowasp-sby -f ser.sby`, `./equiv_core.sh`.
The core properties live in `src/keyer_core.v` under `` `ifdef FORMAL``. The
capture properties are in `capture_props.sv`, which `src/keyer_capture.v`
includes under `` `ifdef FORMAL`` (Yosys's own front end has no `bind` and no
hierarchical references, so a wrapper module could not see the engine's
registers). The `pins.sby` proof now also drives the replay command port
and the serializer write port (SEMANTICS 15.1) freely.
The serializer properties are in `ser_*_props.sv` and read `src/keyer_ser.v`
unchanged: the SEMANTICS 15.1 registers a property names (`crc_m`,
`tx_state`, `crc5`) are turned into ports by Yosys `expose` in `ser.sby`.
Everything else is observed at the engine's ports. The round trip is bounded
to one message byte: with two, `rt_manch` did not finish within several
minutes. `tools/mutate.py` runs the six proof tasks (not the covers) for a
mutant of `keyer_ser.v`.
